# Lovable Master Prompt

Lovable에 붙여 넣는 프롬프트다. 설계 배경과 사용 방법은 [TECH_DESIGN.md](TECH_DESIGN.md) 23번, 빌드 규칙은 22번에 있다.

**사용 순서**

1. Lovable 프로젝트를 만들고, Lovable의 Supabase 통합으로 **기존** Supabase 프로젝트(마이그레이션 0001~0008 적용 완료)를 연결한다.
2. 아래 **§1 Master Prompt**를 Project Knowledge(또는 첫 메시지)에 넣는다. 이 단계에서는 코드를 만들지 말라고 한다.
3. **§2 Phase 프롬프트**를 하나씩 보낸다. 각 Phase가 끝나면 체크리스트를 확인하고 GitHub에 동기화한 뒤 다음으로 넘어간다.
4. Lovable이 SQL·마이그레이션 실행을 제안하면 **거절한다.** 스키마의 정본은 이 저장소의 `supabase/migrations`다.

프롬프트는 영어로 쓰고, 화면 문구는 한국어로 만들게 한다 (TECH 17.25).

## §1 Master Prompt

```text
You are the lead frontend engineer for "persona-automation-agent", an operating console
for AI virtual influencers. Read this whole brief first. Do NOT write code in response to
this message. Reply only with a short summary of the rules you will follow. Features are
requested later, one phase at a time.

==================================================
1. WHAT THIS APP IS
==================================================
The app is the CONTROL CENTER of a pipeline that already exists:

  Lovable (this app) → Supabase (source of truth) → n8n (orchestration)
    → Python bridge on a local PC → ComfyUI → RTX 5080 → Supabase Storage → back to this app

The app shows state and sends commands. It never generates images, never calls an LLM,
never runs workflows. It talks ONLY to Supabase: tables, RPC functions, Storage, Realtime.
Commands go out as Supabase RPC calls; results come back through Realtime and re-fetches.

MVP user journey:
Google login → create a Persona → set its Visual Identity → create a Content Job
→ watch it progress → see generated images in the Asset Library.

==================================================
2. HARD RULES (never break these)
==================================================
1. Never call the Python bridge, ComfyUI, n8n webhooks, an LLM, or any SNS API from the browser.
2. The only environment variables are VITE_SUPABASE_URL and VITE_SUPABASE_PUBLISHABLE_KEY.
   Never add a service_role key, secret key (sb_secret_...), or any other secret to code or env.
3. The database schema already exists and is managed outside Lovable.
   Never create, alter, or drop tables, columns, policies, functions, buckets, or migrations.
   Never suggest running SQL. If something seems missing, stop and tell me instead.
4. Never write the `status` column of content_jobs, automation_jobs, assets, posts or any other
   job table. Their status changes happen only through the RPC functions in section 6
   (the database rejects direct writes anyway). The single exception is personas.status
   ('active' / 'inactive'), which the persona edit form may update.
5. Status values are lowercase and exactly as listed in section 5. Define them once in
   src/lib/status.ts and use only those constants. Never invent states such as PENDING,
   RUNNING, GENERATED, READY, DEAD, RETRY_WAIT.
6. Security comes from Row Level Security. Never treat a frontend filter
   (e.g. user_id = currentUser.id) as a security measure, and never try to work around RLS.
7. No mock data, fake metrics, or placeholder images. Show an empty state when there is no data.
8. Never show fake progress percentages. Show pipeline steps (section 8).
9. localStorage is only for UI preferences (selected persona, theme, sidebar). Never for app data.
10. Keep changes small. Do not rewrite or restyle working code that the current request
    does not mention. Do not add V1/V2 features unless asked.

==================================================
3. STACK
==================================================
React + TypeScript (strict) + Vite, Tailwind CSS, shadcn/ui, lucide-react, React Router,
@supabase/supabase-js v2, TanStack Query (server state), zod (forms and JSON fields).
No Redux or other global state library. Global state = auth session, selected persona,
sidebar collapsed, theme.
Database types: src/types/database.ts generated by `supabase gen types typescript`.
Do not edit that file by hand.

Folder layout:
src/app/ (routes.tsx, providers/), src/components/{ui,common,layout,dashboard,personas,jobs,
assets,automation}/, src/pages/, src/hooks/, src/lib/ (supabase.ts, status.ts, actions.ts,
progress.ts, errors.ts, schemas.ts), src/types/.

==================================================
4. LANGUAGE AND DESIGN
==================================================
All UI copy is KOREAN. Keep technical nouns in English: Persona, Content Job, Asset,
Workflow, LoRA, Prompt. Keep copy in constants under src/lib/ or per-page constants.
Examples: "Content Job을 만들었어요", "콘텐츠 목록을 불러오지 못했어요. [다시 시도]".

Look: a calm, professional AI operations console. Modern, minimal, data-oriented,
desktop-first. Not a generic SaaS template, not a gaming/crypto dashboard, no heavy
glassmorphism, no rainbow colors.
Use shadcn CSS variables as tokens: background, card, border, foreground, muted, primary,
success, warning, destructive, info. Status colors use only these tokens. Light and dark mode.
Font: Pretendard with a system sans-serif fallback; tabular numbers for metrics.
Information order on every page: status → action → result → exception.
Never use color alone to convey status (pair it with an icon and text). Keyboard accessible.

5. DATA MODEL (already exists; read-only for schema)
==================================================
All ids are uuid unless noted. RLS shows only rows of personas owned by the signed-in user.
Tables with persona_id: persona_assets, content_jobs, automation_jobs, assets, posts,
system_errors (nullable), state_transitions. execution_logs has NO persona_id (reach it via
automation_job_id). worker_status and comfy_workflows are global (no persona_id).
For direct inserts/updates send ONLY the writable columns listed below and only the ones that
changed; never send id, user_id, created_by, source, status (except personas), created_at,
updated_at. Sending a non-writable column fails with 42501. Send null (or omit) for empty
optional values, never an empty string "".

users (id = auth.users.id, email, display_name, avatar_url, role 'operator'|'admin')
  - user may update display_name and avatar_url of their own row only.

personas (id, user_id, name, slug, profile_image_path, description,
  personality jsonb, speaking_style jsonb, interests jsonb, background jsonb,
  content_rules jsonb, interaction_rules jsonb, safety_rules jsonb, visual_settings jsonb,
  status 'active'|'inactive', created_at, updated_at)
  - writable (insert and update): name (1-100), slug, profile_image_path, description (≤2000),
    personality, speaking_style, interests, background, content_rules, interaction_rules,
    safety_rules, visual_settings, status. user_id defaults to auth.uid().
  - slug matches ^[a-z0-9-]{1,60}$ and is unique per user (duplicate → error 23505).
  - "Archive" = set status 'inactive' (allowed for personas). No hard delete in the UI.

persona_assets (id, persona_id, asset_type 'base_model'|'lora'|'face_ref'|'style_ref'|
  'character_ref', name, storage_path, metadata jsonb, is_active, created_at)
  - writable: persona_id (insert only), asset_type, name, storage_path, metadata, is_active.
  - Images (face_ref, style_ref, character_ref) are uploaded with
    supabase.storage.from('persona-private').upload('persona/<persona_id>/refs/<uuid>.<ext>', file)
    — the object path has NO bucket prefix — then a row is inserted whose storage_path is
    exactly that same string. Any other path is rejected (403 from Storage, PT422 from the table).
  - The persona profile image follows the same refs path rule; store the path in
    personas.profile_image_path and show it with createSignedUrl (1 hour).
  - There is no bucket for user avatars: users.avatar_url is a URL text field only (no upload).
  - lora rows are registered by FILE NAME only (name = e.g. "gina_v2.safetensors",
    storage_path null). Model files live on the local ComfyUI PC and are never uploaded.

content_jobs (id, persona_id, source, created_by, content_type 'image'|'video'|'carousel'|
  'story'|'text', topic ≤500, prompt ≤4000, prompt_parts jsonb, negative_prompt ≤2000,
  workflow, params jsonb, input_images jsonb, variants 1-4, platform 'instagram'|'tiktok'|'x',
  priority 1-10 (default 5), status, run_number, metadata jsonb,
  created_at, updated_at, completed_at)
  status: 'draft' | 'queued' | 'generating' | 'ready' | 'published' | 'failed' | 'cancelled'
  - writable (insert): persona_id, content_type, topic, prompt, negative_prompt, workflow, params,
    input_images, variants, platform, priority, scheduled_at, metadata. A direct insert always
    becomes a 'draft' owned by you via defaults. Update is allowed only while status is 'draft'.
  - workflow must be a comfy_workflows.id (^[a-z0-9_]+$). completed_at is set when it turns ready.

automation_jobs (id, persona_id, content_job_id, job_type 'prompt'|'generation'|'caption'
  (V1: 'publish'|'analytics'), status, worker 'n8n'|'python', claimed_by, attempts,
  max_attempts, run_after, locked_at, heartbeat_at, started_at, completed_at,
  payload jsonb, result jsonb, error_type, error_code, error_message, created_at, updated_at)
  status: 'pending' | 'processing' | 'done' | 'failed' | 'cancelled'
  "Retry waiting" is NOT a status: status = 'pending' AND attempts > 0 AND run_after > now().

assets (id, persona_id, content_job_id, automation_job_id, asset_type 'image'|'video',
  file_name, storage_bucket, storage_path, public_url, thumbnail_url, mime_type, width,
  height, duration, prompt, workflow jsonb, generation_metadata jsonb, status, created_at)
  status: 'generated' | 'approved' | 'rejected' | 'archived'
  - Generated media is in the PUBLIC bucket "media": use public_url / thumbnail_url directly.

posts (id, persona_id, asset_id, platform, caption ≤2200, hashtags text[] ≤30, status, ...)
  status: 'draft' | 'pending_approval' | 'approved' | 'scheduled' | 'publishing' |
          'published' | 'failed' | 'rejected' | 'cancelled'
  - MVP: the caption draft is shown on Job Detail. caption, hashtags and is_sponsored are
    editable only while posts.status is 'draft' or 'rejected' (caption ≤2200, hashtags ≤30).

execution_logs (id bigint, automation_job_id, step, service 'n8n'|'python'|'comfyui'|'llm'|
  'supabase'|'sns', status 'started'|'succeeded'|'failed', input_data, output_data,
  duration_ms, execution_ref, error, created_at)
  steps: DISPATCH, CLAIM, LLM, COMPLETE, N8N_ERROR (n8n); BUILD, INPUT_UPLOAD, COMFYUI_QUEUE,
  COMFYUI_WAIT, VALIDATE, UPLOAD, COMPLETE (bridge).

system_errors (id bigint, automation_job_id, persona_id, service, step, error_type, error_code,
  message, retryable, resolved, created_at)
  error_type: 'transient'|'api'|'timeout'|'generation'|'validation'|'authentication'|'policy'|'unknown'.
  service is 'n8n' or 'python' in practice. A new row is written on EVERY failed attempt, so most
  rows point to jobs that were later retried; check the job's current status before offering actions.

state_transitions (id bigint, entity_type 'content_job'|'automation_job'|'asset'|'post'|'approval',
  entity_id, persona_id, from_status, to_status, actor_type 'operator'|'n8n'|'python'|
  'agent'|'system', reason, created_at)  — audit trail, used for activity feeds.

comfy_workflows (id text, version, type, stage, enabled, params jsonb, inputs jsonb)
  — selectable workflows; params holds defaults and min/max/enum per parameter.

worker_status (id text, kind 'python'|'n8n', comfyui_ok, gpu jsonb {name, vram_total_mb,
  vram_free_mb}, current_job_id, queue_size, version, models jsonb {checkpoints: string[],
  loras: string[]}, last_seen_at)
  — online if last_seen_at is within 90 seconds. comfyui_ok and gpu are meaningful only for
  kind 'python' (null / {} for n8n, and gpu is {} while ComfyUI is down).

Tables that do NOT exist yet (V1/V2): performance_metrics, approvals, conversations,
messages, fan_memories, ai_decisions. Do not query or create them.

6. RPC FUNCTIONS (the only way to change state)
==================================================
supabase.rpc(name, args):
- create_content_job(p_persona_id, p_content_type, p_topic?, p_prompt?, p_negative_prompt?,
    p_workflow?, p_params?, p_input_images?, p_variants?, p_priority?, p_platform?,
    p_submit = true) → content_jobs row ('queued'; 'draft' if p_submit=false)
- submit_content_job(p_content_job_id)            draft → queued
- cancel_content_job(p_content_job_id, p_reason?) → cancelled (also cancels running steps)
- retry_content_job(p_content_job_id)             failed → queued, from the start
- regenerate_content_job(p_content_job_id, p_variants?)  ready → queued, more variants
- retry_automation_job(p_job_id)                  failed step → pending (retry only that step)
- archive_asset(p_asset_id)
- resolve_system_error(p_error_id)                p_error_id is a bigint
- get_dashboard_summary(p_persona_id?) → jsonb {
    personas, content_jobs: {<status>: count}, automation_jobs: {active, pending, retry, failed},
    recent_failures: [...5], workers: [{id, kind, comfyui_ok, online, current_job_id,
    queue_size, last_seen_at}], publishing_enabled }
  content_jobs only contains statuses with count > 0 (missing key = 0).
  automation_jobs.failed is an ALL-TIME count (it includes failed steps of jobs that were later
  retried from the start or cancelled): use it only for the /automation queue numbers.
- get_app_settings(), update_app_setting(p_key, p_value)   admin only

Errors come back as { code, message, details }: code is a SQLSTATE, message is our code,
details is English technical text.
  PT403 → "권한이 없어요" (admin-only action, or no operator profile)
  PT404 → "찾을 수 없어요"
  PT409 → "지금 상태에서는 할 수 없어요" and re-fetch the data
  PT422 → "입력값을 확인해 주세요" near the form (map known details such as
          "topic or prompt is required" to the matching field; show raw details only inside
          "기술 정보 보기")
  PT429 → "실행 한도에 도달했어요"
  23505 → duplicate value (e.g. slug); 23514 → value out of the allowed range
  42501 → permission denied on a column/table: this is OUR bug (we sent a non-writable column)
  PGRST301 / PGRST303 / HTTP 401 → session expired → sign in again
  PT500 or anything else → generic sentence; network failure → "연결할 수 없어요".
Change state only after the server responds (no optimistic updates except UI toggles).
```

|---|---|
| "전체 시스템을 한 번에 만들어줘" | 구조가 무너지고 고치기 어렵다 |

| "service role key로 해결해줘" | RLS가 무력화되고 키가 공개된다 |
| "테이블(또는 칼럼)을 하나 추가해줘" | 스키마는 이 저장소의 마이그레이션으로만 바꾼다 (TECH 21.3) |
| "AI로 프롬프트를 다듬는 버튼을 넣어줘" | 브라우저에서 LLM을 부르게 된다. 17.25에서 미리보기 없음으로 확정 |
